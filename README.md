# Wine Sommelier Assistant

Учебный проект для курса Математические Методы Анализа Данных.

## Быстрый старт (Локальный запуск)

### Требования к окружению
- **Python:** версия **3.10, 3.11, 3.12, 3.13 или 3.14** (протестировано на Python 3.14).

### 1. Клонирование / переход в папку приложения
```bash
cd wine_app
```

### 2. Создание и активация виртуального окружения
```bash
python3 -m venv .venv

# На Linux / macOS:
source .venv/bin/activate

# На Windows:
# .venv\Scripts\activate
```

### 3. Установка зависимостей
```bash
pip install --upgrade pip
pip install -r requirements.txt
```

### 4. Запуск приложения
```bash
streamlit run app.py
```

## Структура проекта `wine_app/`

- `app.py` — основной скрипт веб-приложения с интерактивным интерфейсом, вкладками и графиками.
- `model.joblib` — сериализованный итоговый пайплайн (`StandardScaler` + `LogisticRegression`), обученный на обучающей выборке.
- `config.json` — конфигурационный файл с сохраненным оптимальным порогом классификации (`threshold`), подобранным по $F_1$-score на валидации.
- `test.csv` — тестовая выборка с 12 признаками и истинными экспертными оценками `target`.
- `requirements.txt` — список необходимых библиотек с версиями.
- `README.md` — данная инструкция и теоретические ответы.

## Функционал приложения

1. **Оценка одного вина:**
   - Интерактивный ввод всех 12 физико-химических признаков вина.
   - Граничные диапазоны и значения по умолчанию взяты по медианам тестового датасета.
   - Мгновенный расчет вероятности и вывод вердикта модели с учетом текущего порога.

2. **Модельные метрики:**
   - Динамический пересчет матрицы ошибок (Confusion Matrix) и метрик: Precision, Recall, $F_1$-score, Accuracy при любом положении ползунка порога.
   - Отрисовка ROC- и PR-кривых с нанесением текущей рабочей точки классификатора.
   - Текстовое пояснение для сомелье о балансе точности и охвата.

3. **Пакетное предсказание:**
   - Загрузка пользовательского CSV-файла с партией вин.
   - Защита от сбоев: валидация наличия всех 12 обязательных столбцов с понятным сообщением об ошибке в случае несовпадения колонок.
   - Скачивание обработанного файла с предсказанными вероятностями и решениями.
   - Возможность скачать готовый шаблон CSV для быстрого тестирования.

4. **Что выучила модель:**
   - Горизонтальная столбчатая диаграмма стандартизированных коэффициентов логистической регрессии.
   - Детальное описание химических факторов, повышающих и понижающих качество вина.

## Кэширование в Streamlit (Ответы на задание 4.5)

### 1. Почему для модели используется `st.cache_resource`, а для таблиц — `st.cache_data`?
- **`st.cache_resource`** предназначен для глобальных ресурсов, сетевых соединений и тяжелых недетерминированных или неделящихся объектов (таких как обученные модели ML). Модель создается в памяти один раз на весь сервер как singleton и разделяется между всеми пользовательскими сессиями без копирования и сериализации.
- **`st.cache_data`** предназначен для сериализуемых данных, возвращаемых по значению (pandas DataFrames, numpy массивы, словари). Streamlit кэширует их с защитой от мутаций (mutation guard), возвращая защищенную копию, чтобы изменение данных в одной пользовательской сессии не повлияло на другие.

### 2. Что изменится, если вызвать `joblib.load` без декоратора?
Streamlit перезапускает весь скрипт `app.py` сверху вниз при **каждом** действии пользователя (сдвиг слайдера, переключение вкладки, ввод значения). Без декоратора `@st.cache_resource` файл `model.joblib` читался и десериализовался бы заново с диска при каждом малейшем движении ползунка. Это привело бы к:
- сильным лагам и зависанию веб-интерфейса;
- огромному числу избыточных дисковых операций ввода-вывода (Disk I/O);
- повышенной нагрузке на процессор и утечкам оперативной памяти.
